All three implementation additions were subsequently tested locally on 2026-09-22 and passed their declared scopes: DiffLiB's 3620 s quickstart plus a short single-component gradient comparison; BattMo.jl's default 0.5C discharge with controller-stop verification; and cideMOD's Chen 2020 P2D reference test. The inventory now has 19 successful implementation records and 3 older unreproduced records. BattMo.jl belongs to the existing BattMo project, not a new project: there are 21 projects and 22 implementation-level test records. PyBattMo and BattMoApp are documented under BattMo without adding project or test counts.

[DandeLiion](https://www.dandeliion.com/about) was considered but not added as an open-source solver: the official site describes a hosted solver and commercial licensing; this review did not verify an open license for the solver implementation. A public API client does not establish that the solver is open source.

## Legacy retest scope

The GitHub default-branch SHAs of all three previously unreproduced models still match the May records. Therefore these are environment/diagnostic retests of unchanged sources, not tests of upstream fixes.

- [hanrach](REPRODUCTIONS/p2d-solver-hanrach.md): native arm64 JAX 0.4.30 reduced grid passed with residual `5.413805508102402e-10` and failure flag 0. Original 50 grid received SIGKILL (child code -9); no OOM cause was independently established. The upstream driver runs one Newton solve, not a time trajectory.
- [dkong](REPRODUCTIONS/p2d-model-dkong8s93.md): Octave first-Newton-step diagnostic with plotting bypassed; not a complete 720-second simulation.
- [decaluwe](REPRODUCTIONS/p2d-li-ion-battery-decaluwe.md): native launch and source inspection; historical container DAE results were not reproduced in this pass because Docker was unavailable.

The reusable [probe script](scripts/retest_legacy.py) copies the existing ignored upstream checkouts to a temporary directory. It does not download code or modify those checkouts. It returns nonzero on timeout or process failure. The dkong probe intentionally only diagnoses the first step; its zero exit status is not full-model success.
